# ADR-0001 — Arquitetura Baseada em Capacidades

| Campo | Valor |
|-------|--------|
| ADR | 0001 |
| Título | Arquitetura Baseada em Capacidades |
| Status | Aceito |
| Data | 2026-07-27 |

---

# Contexto

A Operational Intelligence Platform (OIP) foi inicialmente concebida como uma plataforma composta por diversos microsserviços especializados em vídeo, áudio, despacho, IA e monitoramento.

À medida que a plataforma evoluiu, observou-se que modelar funcionalidades como "Detector de Placas", "Detector de Pessoas" ou "Detector de Incêndio" criava forte acoplamento entre a infraestrutura e os modelos de Inteligência Artificial.

Além disso, essa abordagem dificultava:

- reutilização de componentes;
- evolução independente;
- integração de soluções desenvolvidas por terceiros;
- experimentação científica;
- atualização contínua dos modelos.

Foi então adotado um novo paradigma arquitetural.

---

# Decisão

A OIP passa a ser definida como uma **Plataforma de Capacidades (Capability Platform)**.

A plataforma não conhece detectores específicos.

Ela conhece apenas **Capabilities**.

Cada Capability representa uma capacidade operacional que pode produzir conhecimento para a plataforma.

Exemplos:

- Vehicle Intelligence
- Person Intelligence
- Audio Intelligence
- PPE Intelligence
- Fire Intelligence
- Face Intelligence
- Crowd Intelligence
- Weapon Intelligence
- License Plate Intelligence
- Speech Intelligence

Cada Capability é completamente desacoplada da plataforma principal.

---

# Toda Capability é um Plugin

Uma Capability é distribuída independentemente.

Ela possui:

- manifesto (CSpec)
- modelos
- configuração
- documentação
- contratos
- runtime
- pipeline interno

A plataforma apenas:

- instala
- inicia
- monitora
- atualiza
- remove

Capabilities.

---

# Comunicação

Nenhuma Capability chama outra diretamente.

Toda comunicação ocorre através do barramento de eventos.

```
Capability A
        │
        ▼
     NATS JetStream
        ▲
        │
Capability B
```

Isso elimina dependências diretas.

---

# Plataforma Orientada a Eventos

Toda informação produzida por uma Capability é publicada como eventos.

Exemplo:

```
vehicle.detected

vehicle.color.detected

vehicle.plate.read

person.detected

fire.detected

audio.transcribed

speech.intent.classified
```

Nenhuma Capability depende da implementação interna de outra.

---

# Processadores

Uma Capability é composta por Processors.

Exemplo:

Vehicle Capability

```
Detector

↓

Tracker

↓

Crop Generator

↓

OCR

↓

Classifier

↓

Publisher
```

Cada Processor executa apenas uma responsabilidade.

---

# Agregação

A plataforma não trabalha diretamente com inferências.

Ela trabalha com conhecimento consolidado.

Esse conhecimento é produzido pelo Correlation Engine.

```
Eventos

↓

Aggregation

↓

Knowledge

↓

Search

↓

Alert

↓

Dashboard
```

---

# Active Learning

O treinamento nunca acontece durante a inferência.

A inferência apenas produz dados.

O aprendizado ocorre posteriormente através de:

- correções humanas;
- validação operacional;
- datasets;
- pipelines de treinamento.

---

# Versionamento

Cada Capability possui ciclo de vida independente.

Uma nova versão não exige atualização da plataforma.

A OIP apenas valida compatibilidade através do Capability Specification.

---

# Benefícios

Esta decisão proporciona:

- arquitetura modular;
- desacoplamento;
- alta escalabilidade;
- desenvolvimento distribuído;
- suporte a terceiros;
- atualização independente;
- experimentação científica;
- múltiplas implementações para a mesma Capability;
- compatibilidade futura.

---

# Consequências

## Positivas

- Baixo acoplamento.

- Maior reutilização.

- Evolução independente.

- Ecossistema aberto.

- Facilidade para pesquisa científica.

- Facilita integração academia-indústria.

- Suporte a Marketplace de Capabilities.

---

## Negativas

- Maior complexidade inicial.

- Necessidade de contratos extremamente bem definidos.

- Forte dependência da infraestrutura de eventos.

- Maior necessidade de observabilidade.
